## Common Development Commands

The package manager is **bun** (`bun.lock`, `bunfig.toml`); npm works as a fallback.

```bash
bun install        # Install dependencies
bun run dev        # Launch Vite development server
bun run build      # Full production build: Vite -> Nitro (.output/)
bun run start      # Run production server (node scripts/serve.mjs)
bun run preview    # Vite preview server
bun run lint       # ESLint check
bun run format     # Prettier formatting
```

Verification gate before committing:

```bash
bun run lint && bun run build
```

Both must pass with 0 errors. There is no automated test runner configured; verification is static analysis and production build.

## Critical Architecture & Data Flow

### 1. The 3-Tier Data Fallback Chain

**All page content (profile, experience, projects, certifications) is data, not hardcoded JSX.**
All reads and writes are centralized in [src/lib/portfolio-data.ts](src/lib/portfolio-data.ts):

1. **Supabase** (`projects`, `experience`, `certifications`, `profile` tables) — source of truth when configured (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`).
2. **localStorage cache** (`portfolio_*_data` keys) — used when Supabase is unreachable, unconfigured, or returns empty.
3. **`INITIAL_*` constants** in `src/lib/portfolio-data.ts` — committed seed defaults. This is what renders on fresh browser sessions and initial deploys.

> [!IMPORTANT]
> **To change default portfolio content, edit `INITIAL_*` in `src/lib/portfolio-data.ts`.**
> Editing via `/admin` only writes to Supabase/localStorage and will not persist to git or display to fresh visitors without Supabase credentials.

### 2. Database vs TypeScript Field Naming

Supabase columns use `snake_case` (e.g. `student_status`, `portrait_url`, `resume_url`), while TypeScript types use `camelCase`.
Mapping is explicitly handled in `src/lib/portfolio-data.ts` (`getPortfolioData()` and `saveProfile()`).
If adding a new profile or project property:

1. Update `src/types/portfolio.ts`
2. Update `supabase-schema.sql`
3. Update read and write mappings in `src/lib/portfolio-data.ts`
4. Update the respective component in `src/components/admin/`
5. Update `src/routes/index.tsx`

### 3. Route Structure

- [src/routes/index.tsx](src/routes/index.tsx) — Main portfolio landing page containing Hero, Projects, About, Experience, Certifications, and Contact.
- [src/routes/admin.tsx](src/routes/admin.tsx) — Administrative panel wrapping `src/components/admin/AdminLayout.tsx`.
- [src/routes/\_\_root.tsx](src/routes/__root.tsx) — Root HTML shell, metadata (OpenGraph, Twitter cards, JSON-LD), error boundaries, and stylesheet link.
- `src/routeTree.gen.ts` is auto-generated by TanStack Router. **Never edit it manually.**

### 4. Media & Static Assets

- Media files are located in `public/content/` and referenced by root-relative paths (e.g., `/content/idcard_ai.mp4`).
- Do not add duplicate media directories at the repository root.
- `scripts/serve.mjs` implements HTTP range requests specifically to support `<video>` seeking in production environments.

### 5. Error Handling Pipeline

Three interconnected error boundaries exist:

1. `src/server.ts` — Unwraps h3 HTTP error envelopes (`{"unhandled":true,"message":"HTTPError"}`) into rendered error pages.
2. `src/start.ts` — Intercepts non-HTTP exceptions.
3. `src/routes/__root.tsx` — React `errorComponent` and `notFoundComponent` reporting through `src/lib/lovable-error-reporting.ts`.
   Do not bypass or remove these layers.

## Safety Rules for Autonomous Agents

1. **Lovable Git History Preservation**: NEVER force-push (`git push -f`), rebase, squash, or amend published commits. Every push auto-deploys.
2. **Vite Plugin Configuration**: `@lovable.dev/vite-tanstack-config` bundles plugins. Do not manually add duplicate React, Tailwind, or TanStack plugins to `vite.config.ts`.
3. **Dependencies**: `bunfig.toml` specifies `minimumReleaseAge = 86400`. Do not install newly published zero-day packages.
4. **UI Components**: Built on shadcn/ui over Radix UI located in `src/components/ui/`. Reuse existing components instead of introducing third-party UI libraries.
5. **No Fabricated Facts**: Project metrics, dates, and credentials must match verified source data (the official résumé and confirmed user details).
